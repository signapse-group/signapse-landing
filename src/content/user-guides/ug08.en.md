## Goal

Recognize missing data or unavailable features, perform checks within your permissions, and know when you need help.

## Prerequisites and permissions

This guide is for people who have already been granted access to Signapse. Being able to sign in does not grant permission to use every feature.

Before checking, note the page you are viewing, the on-screen message, and the selected workspace. On screens with asset, time, or filter selections, note those selections too. Keep a copy of unsaved content before leaving or reloading the page.

## Steps

### 1. A menu item is missing or an action is unavailable

Check that you are using the intended account and have opened the app navigation menu. If the page or action requires a workspace, check the current workspace before continuing.

If the interface reports a permission restriction, read the description and any required permission displayed. See [Account, permissions and limits](/en/docs/ug02); if a permission restriction still blocks you, contact the person who granted you access to check your account.

A missing menu item or unavailable button alone does not establish a system error. Some actions depend on permissions, a workspace, selected data, or processing status. If the cause is unclear, note the symptom rather than assuming a permission restriction.

### 2. The page opens, but data is empty or incomplete

Check the scope applied by the screen: workspace, asset, time range, search terms, and filters when available. Read the message in the affected area; one part of a page may have data while another does not.

| Symptom                                                                                | Checks and next action                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| No active workspace or no tracked assets                                               | Choose the intended workspace; if you have permission, create a workspace or add assets and save the list using [Workspaces and watchlists](/en/docs/ug03).                                                                                      |
| The event list returns no results                                                      | Review the search terms and active filters. Clear the search terms or adjust the filters as appropriate, then check again.                                                                                                                       |
| An event has a description but shows **No evidence yet** or has no source article link | Note that you could not check the supporting sources. See [Reading news, events and evidence](/en/docs/ug05); do not assume the event has been verified.                                                                                         |
| The chart has no candle data for the selected asset                                    | Check the watchlist asset and time range. See [Reading market charts](/en/docs/ug06). No candles in the current range does not mean the price stayed unchanged.                                                                                  |
| An AI answer lacks evidence or states data limitations                                 | Read the stated limitations and available sources, and note what still lacks support. See [Working with the AI Assistant](/en/docs/ug07).                                                                                                        |
| Telegram notifications have not arrived                                                | When you have permission to view them, check the bot, destination, and workspace routing states using [Setting up Telegram](/en/docs/ug10). Saved settings or a ready state do not prove that a notification was sent and received successfully. |

Empty data describes the result in the current scope. Do not treat it as evidence that there are no market events or that every asset has the same data coverage.

### 3. The interface reports a loading or saving error

Read the message to distinguish a loading error, invalid input, an account limit, or a saving error. If it identifies something to correct, adjust it within your permissions; see [Account, permissions and limits](/en/docs/ug02) for limits.

For loading errors, use **Retry** if the affected area provides that button. For charts, use the reload action shown on the screen. If the error persists, note the message and when it occurred so you can seek help.

For saving errors, keep the content you are editing and check the current state before submitting again. Tracked asset changes in particular may have been saved only partly: compare the current list with the list you want, then adjust and save again if needed. Do not assume that all changes failed or all succeeded.

## Expected result

You can identify the symptom, have checked the relevant scope and conditions, and can either continue or identify what needs help. Treat changes as saved only after checking the result; continue to mark missing data or evidence as information you could not verify.

## Troubleshooting

If the problem persists after these checks, prepare the page name, time of occurrence, actions taken, error message, and relevant workspace, asset, or time range when applicable. Explain the expected and actual results so the person helping you can check the right situation.

Contact the person who granted you access so they can receive the issue and refer it to the appropriate person if needed. This is your contact for permission restrictions and data, loading, or saving problems you could not resolve yourself.

When sharing support information, do not send passwords, Telegram bot tokens, or access keys; hide unnecessary private information in screenshots.
