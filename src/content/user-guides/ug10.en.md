## Goal

Connect a Telegram bot, link a receiving conversation, and choose where workspace notifications go. Check saved settings, test messages, and actual market notifications separately.

## Before you start

- Sign in to the correct Signapse account.
- You can use Telegram and the intended conversation. For a group, you must be allowed to add the bot and let it send messages there.
- You have an active bot in Signapse or the token of a bot you are allowed to connect. Bot tokens are secret; keep them out of screenshots and support requests.

## Steps

### 1. Open settings and check the workspace

Under **System configuration**, select **Telegram integration**. Check the selected workspace before configuring **Feature routing**; each flow's destination is configured per workspace. See [Workspaces and watchlists](/en/docs/ug03) if you need to switch workspaces.

### 2. Connect a bot

If a suitable bot is already **Active**, check its name and `@username`, then continue to destination linking.

If you need a new bot, open the [official BotFather](https://t.me/BotFather), send `/newbot`, and follow its name and username prompts to obtain a token. See [Telegram's instructions](https://core.telegram.org/bots/features#creating-a-new-bot).

In **Telegram bot**:

1. Select **Connect bot**.
2. Paste the token into **Bot token**, then select **Connect bot** in the dialog.
3. Wait for the result and check that the bot appears with the correct identity and **Active** status.

The token is not displayed again after connecting.

### 3. Link a destination

If the intended destination is already active with the correct **Linked bot**, continue to sending a test. Otherwise:

1. In **Destinations**, select **Link destination**.
2. Select the correct **Bot receiving /start**, then **Create link command**.
3. Check the command’s expiry, then choose a linking method below.

**Private chat:** select **Open private chat**, check the bot, and send the link command in that conversation. Use **Copy command** if you need to paste it into Telegram.

**Group:** select **Open group chat** and choose the group that will receive messages. Add the bot if needed, then send the complete copied link command in that group. The bot must be allowed to receive commands and send messages there.

After sending the command, return to Signapse and select **Refresh destinations**. Check the conversation name, **Linked bot**, and **Active** status in the list.

A link command is different from a bot token; never send your bot token into a conversation. If the command expires, select **Generate a new link command** and use the new one. Creating a command or refreshing the list alone does not complete linking.

### 4. Send a test and check Telegram

At the intended destination, select **Send test** once and wait for the result. Open Telegram and check for a new test message from the correct bot in the correct conversation.

Compare the successful-send message in Signapse with what you actually see in Telegram. If the request times out and the result is uncertain, check Telegram before retrying to avoid duplicate messages.

### 5. Choose the destination, language, and enabled state

In **Feature routing**, check the **Workspace** column and the flow you intend to configure, such as **Market news alerts**.

1. Under **Destination**, choose the conversation you checked. If the flow is already enabled, this change may redirect subsequent notifications as soon as it saves; check the destination carefully before selecting it.
2. Under **Output language**, choose a supported language for a flow that offers this choice. Alternatively, choose **Use the owner's preferred language (or the system default)**. Personal preferences are explained in [Account and usage limits](/en/docs/ug02); changing notification language does not change the interface language.
3. Use **Sending enabled** to enable the flow when you want messages; turn it off to leave that flow **Paused**.

Changes save immediately. Wait for the result before changing the next setting; if an error occurs, check the saved values.

### 6. Check settings and actual notifications

Reopen the routing area and confirm the workspace, flow, destination, language, and enabled or paused state. When you switch workspaces, check that workspace's routing again.

For **Market news alerts**, an event must have been enriched with context and relate to at least one asset in the workspace watchlist. The enabled route, destination, and bot must also meet operating conditions; a new article appearing in Signapse does not necessarily trigger an alert for you. Check the watchlist using [Workspaces and watchlists](/en/docs/ug03).

When an actual market notification arrives, compare the bot, conversation, content, and receipt time. No new message does not by itself establish incorrect settings. Enabling a flow also does not confirm that earlier messages will be resent.

## Expected result

You can distinguish three outcomes:

| Outcome                      | How to check                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Settings saved               | The correct bot and destination are active; routing shows the intended selections in the relevant workspace.       |
| Test message received        | You see a new test message from the correct bot in the correct Telegram conversation.                              |
| Market notification received | You see an actual notification from the intended flow in that conversation; this is separate from the test result. |

## Troubleshooting

| Sign                                             | Action                                                                                                                                                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Missing menu, read-only area, or disabled action | Check the workspace and on-screen message; see [Missing data or features](/en/docs/ug08).                                                                                                                     |
| Bot connection fails / bot is not active         | Check that you used the token for the correct bot you are allowed to manage and read the displayed error. Do not share the token for troubleshooting; see [Missing data or features](/en/docs/ug08) for help. |
| No destination after creating the command        | Check that you completed the Telegram steps with the correct bot and conversation before refreshing. Generate a new command if it expired.                                                                    |
| Test fails or no message appears                 | Check that the destination and bot are active, the conversation is correct, and the bot is not blocked and may send there. If the request timed out, check Telegram before resending.                         |
| Cannot choose a destination or enable a flow     | Check that a workspace is selected and an active destination exists. Read the error instead of assuming the action saved.                                                                                     |
| Language list fails to load                      | Keep the current selection and try loading again; do not assume the language changed.                                                                                                                         |
| Test received but no market alerts               | Check the workspace, watchlist, flow, destination, and enabled state. Market news alerts require an enriched event related to a tracked asset; a test does not establish that this condition has been met.    |
| Saving fails or the problem persists             | Check the current state before retrying. Note the workspace, flow/destination name, time and timezone, steps taken, and error with secrets removed; see [Missing data or features](/en/docs/ug08).            |

See also [Missing data or features](/en/docs/ug08) and [Glossary and data states](/en/docs/ug09).
