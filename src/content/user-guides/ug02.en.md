## Goal

Identify the account you are using, update permitted personal settings, understand access permissions, and read current usage and limits before continuing an action.

This guide is for people who have already been granted access to Signapse. See [Getting started with Signapse](/en/docs/ug01) for your first session.

## Account

### Check the account you are using

Open the user menu at the bottom of the app navigation and select **Account**. Check your personal information and **Email address** to confirm that you are using the account that was granted access. The sign-in email is read-only here.

If you are using the wrong account, keep a copy of unsaved content, select **Sign out** in the user menu, and sign in again with the appropriate account.

### Update personal information

Under **Personal information**, edit the fields the interface permits, including **First name**, **Last name**, **Date of birth**, and **Phone number**. Complete required fields, correct any information marked invalid, and select **Save changes**. Check the success message and the information displayed after saving.

The save button may be unavailable when nothing has changed, the data is invalid, or a save is in progress. Select **Restore** to discard unsaved edits in the form.

### Personal preferences

- **Interface language:** open the language selector at the top of the app and choose the language you want to use.
- **Light or dark appearance:** open **Choose theme** and choose **Light**, **Dark**, or **System**.
- **Default Telegram language:** on the **Account** page, choose a supported language under **Default Telegram language**, select **Save language**, and check the saved language. This preference applies when Telegram notifications use **Default** language; interface language is selected separately. See [Setting up Telegram](/en/docs/ug10) to configure notification delivery.

## Permissions

Signing in successfully does not grant access to every feature. Permission to view data and permission to perform an action may differ; being able to view a page does not necessarily allow you to create or edit its data.

| Feature group             | What to distinguish                                                                                                                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspaces and watchlists | Choosing/viewing a workspace, creating or renaming one, and reading or managing tracked assets have separate permission conditions. See [Workspaces and watchlists](/en/docs/ug03). |
| Market information        | Reading events, articles, and charts depends on the relevant permissions. The **View article** link on evidence also depends on article reading permission.                         |
| AI Assistant              | Permission to use AI and the AI turn limit are separate conditions. See [Working with the AI Assistant](/en/docs/ug07).                                                             |
| Telegram                  | Viewing or changing each configuration area depends on your granted permissions. See [Setting up Telegram](/en/docs/ug10).                                                          |

If the interface reports a permission restriction, read the description and required permission name when available. A hidden menu item or unavailable button may also result from a missing workspace, unselected data, or processing status; see [Missing data or features](/en/docs/ug08) to distinguish these cases. Contact the person who granted access to check your account permissions or request a change.

## Limits

Open the user menu and select **Usage limits** to expand its details within the menu; select it again to collapse them. Wait for the values to load, then read **Used / limit** and the scope of each metric.

| Metric                    | How to read it                                                                                                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Workspaces**            | Workspaces used compared with the limit returned for your account.                                                                                                 |
| **Watchlist assets**      | The limit applies per workspace; match each workspace row with the list you are managing.                                                                          |
| **AI turns**              | Completed AI conversation turns this month compared with the limit. Read the displayed **Resets** time and **UTC** time zone.                                      |
| Active analysis schedules | Schedules with ACTIVE status compared with the account limit, across workspaces. This is a usage metric; this guide does not cover creating or changing schedules. |

Use the current values in the app to check your account status. Do not assume that all accounts have the same limits or that every metric resets at the same time.

If the section fails to load, select **Retry**. Unavailable usage data does not mean usage is zero or the account has no limits.

## Recognizing and handling limits

When an action is blocked, read the message to distinguish missing permissions, a reached limit, invalid input, or a loading or saving error.

If the message reports a limit, open **Usage limits** and check the relevant metric and workspace. For watchlists, review the selected asset count before saving; if you need to remove assets you no longer follow, do so deliberately using [Workspaces and watchlists](/en/docs/ug03). For AI turns, check usage and the displayed reset time before trying again.

If the cause is unclear or you need a permission or limit change, contact the person who granted access. Provide the blocked action, message, and relevant metric; a support request does not confirm that permissions or limits have changed. For loading or saving problems you could not resolve, follow [Missing data or features](/en/docs/ug08).
